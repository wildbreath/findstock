# 沪深A股自动筛选系统

按用户选择的交易日, 自动筛选满足量价条件的沪深A股, 并提供分级板块总览和涨停连板天梯复盘。

板块总览基于真实涨停池与东方财富当前行业归属，展示连板分布、板块层级及池内个股。

---

## 一、筛选规则

设用户选择的交易日为 `D2`, 系统按**交易日历**回溯出 `D1`(上一个交易日)、
`D0`(上上个交易日)。一只股票必须**同时**满足以下全部条件:

```text
D1成交量 / D0成交量 > 2
D2成交量 / D1成交量 > 2

0% < D0涨幅 < 7%
0% < D1涨幅 < 7%
0% < D2涨幅 < 7%

D2 简称不含 ST / *ST

D0、D1、D2 三天均有完整有效、且为正常交易状态的行情数据
```

规则要点:

| 项 | 说明 |
| --- | --- |
| 量比 | **严格大于 2**。正好 2 倍不符合; 用整数比较 `今日量 > 2 × 昨日量`, 无浮点误差 |
| 涨幅 | **开区间 (0%, 7%)**。等于 0% 或等于 7% 都不符合 |
| 涨幅来源 | 数据源提供的当日涨跌幅 (不复权口径), 用 `Decimal` 精确比较 |
| ST 判定 | 以 **D2 当天**由数据源按日期返回的股票简称为准 (`ST` / `*ST` / 大小写 / 全角写法), 不用股票今天的名称代替历史状态。详见下文「关于 ST 判定」 |
| 停牌 | 停牌日 `tradestatus = 0` 或成交量/涨幅为空, 一律按 "数据不完整" 排除 |
| 次新股 | 上市时间不足三个交易日 (D0 之前没有交易记录) 的股票排除 |

### 筛选漏斗

结果页会展示逐级收窄的过程, 便于核对规则是否按预期生效:

```text
候选股票 (三个交易日中出现过的沪深A股)
  └─ 且三天数据完整、均正常交易
       └─ 且上市满三个交易日
            └─ 且三日涨幅均落在 (0%, 7%)
                 └─ 且连续两次成交量翻倍
                      └─ 且 D2 非 ST  ←  最终结果
```

### 市场范围

仅沪深A股: `sh.60*`、`sh.68*`(科创板)、`sz.00*`、`sz.30*`(创业板)。
**排除**北交所 (`bj.*`)、B股 (`sh.900*` / `sz.200*`)、ETF/基金、可转债、指数。

## 二、快速开始

### 1. 安装依赖

```powershell
python -m pip install -r requirements.txt
```

### 2. 一键启动 (推荐)

双击项目根目录下的 **启动系统.bat**, 或双击桌面上的 **沪深A股筛选系统** 图标。
启动器会自动完成:

1. 检查运行依赖, 缺失时自动执行 `pip install -r requirements.txt`;
2. 检测服务是否已经在运行 —— 已在运行就直接开浏览器, 不会重复启动;
3. 默认端口被占用时, 自动改用下一个空闲端口;
4. 启动 Web 服务, 就绪后**自动打开浏览器**;
5. 在控制台打印本地数据概况, 并提示是否需要初始化。

按 `Ctrl+C` 或直接关闭窗口即可停止服务。

桌面快捷方式可以随时创建或删除:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install_shortcut.ps1          # 创建
powershell -ExecutionPolicy Bypass -File scripts/install_shortcut.ps1 -Remove  # 删除
```

> `启动系统.bat` 刻意只包含 ASCII 字符: `cmd.exe` 会用当前 OEM 代码页解析 `.bat`,
> 文件里出现非 ASCII 注释会被解析成命令而报错。所有中文提示都由
> `scripts/launcher.py` 输出, 窗口标题也由 Python 通过 Win32 API 设置。

### 3. 初始化数据 (首次使用)

首次需要把最近两年的日线行情下载到本地。启动后在页面上点击
**初始化 (下载最近两年)** 即可。

也可以在命令行直接跑全量下载:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/init_data.ps1
```

> **耗时说明**: 数据源按 "每只股票一次请求" 提供日线, 沪深A股约 5200 只,
> 因此首次全量下载需要较长时间 (视网络与数据源负载, 通常在 30~90 分钟)。
> 下载是**可恢复**的: 中途失败或中断后重新执行, 已完成的部分不会重复下载。
> 之后只需要 "增量补充新交易日", 秒级到分钟级即可完成。
>
> 注意: 新浪日线接口每次都会返回该股票的**整段历史**再按日期截取, 所以
> "只补三个交易日" 与 "下载最近两年" 的请求数量和耗时几乎一样。既然如此,
> 建议首次直接点 **初始化 (下载最近两年)**, 一次性把数据备齐。

### 4. 使用

界面分为七个页面, 用**左侧导航栏**的 **总览** / **条件选股** / **连板天梯** / **复盘表** / **自选股** / **多股同列** / **数据** 切换
(窄屏时导航栏折成顶部横条)。

**总览页面** (``/``)

默认展示所选交易日的连板股（≥2 板），可切换为全部涨停股、排除 ST，按数量或高度排序。
一级、二级行业使用东方财富真实板块 ID 分组；点击一级板块查看该板块个股及其中的二级行业，
再点二级板块继续查看个股。行业按股票代码去重，多归属股票可在多个板块出现。
数据日期、来源、是否收盘定稿、板块归属获取时间，以及未完成、失败、旧缓存均会明确提示，
失败可重试。缺少分级不根据涨停池行业名猜测。行业为当前归属，不代表历史归属或涨停原因。
板块内只列当前股池的连板/涨停股，不是全部成分股；点击股票名称可打开 K 线。

**条件选股页面** (``/screen``)

标题下有两个独立子页面：**策略设计**（`/screen/strategies`）用于编辑、复制、保存策略，
**股票筛选**（`/screen/stocks`，也是 `/screen` 的默认内容）用于选择策略、直接调参、选择日期和查看结果。
两页通过顶部子导航切换；“编辑条件”和“去筛选”会携带当前策略选择。

1. 在页面内的日历中点选日期 (日历是唯一的日期选择入口, 没有日期输入框)。
   日历顶部可直接选择**年份**和**月份**下拉框跳转, 也可以用 `‹` / `›` 前后翻月;
   下拉框只列出本地交易日历覆盖的月份, 超出范围的月份会置灰。
   若所选日期不是交易日, 系统会提示并推荐最近一个数据完整的交易日。
2. 在股票筛选页上方的策略列表中点击策略，支持按名称或条件搜索，并记住上次选择。
   在日历右侧的 **本次使用** 中直接修改参数，无需展开、跳转或保存即可筛选和扫描整月。
   **恢复参数** 可撤销临时调整；**保存参数** 可保留参数，保存失败会保留输入。
   临时参数在切换策略或离开页面后不保留。添加、删除条件仍在策略设计页完成。

   早期版本的"标准参数"面板等价于内置的 **标准策略**:

   | 区间 | 默认 | 说明 |
   | --- | --- | --- |
   | 成交量比值 第一次 (D1 ÷ D0) | (2 倍, +∞) | 下限/上限都能改, 想只筛放量温和的股票就填上限 |
   | 成交量比值 第二次 (D2 ÷ D1) | (2 倍, +∞) | 同上 |
   | 涨跌幅 D0 / D1 / D2 | (0%, +7%) | **下限填负数是允许的跌幅, 上限填正数是允许的涨幅**, 例如 -5 ~ +9 表示三天里可以回调 5%、也可以上涨 9% |

   区间两侧都能留空 (留空 = 该方向不限制), 每条区间还有 **含边界值 (≥ / ≤)**
   开关: 勾选为闭区间 `[a, b]`, 不勾选为开区间 `(a, b)`。筛选后切换策略时,
   或修改参数后，页面会提示 "参数已变化，请重新筛选"。
3. 点击 **开始筛选**。
4. 查看 "用户选择的日期 / 实际三日 / 本次参数 / 命中数量 / 筛选漏斗 / 结果表",
   导出 CSV 时会带上产生当前结果的参数；参数修改后需重新筛选才能导出，保证文件与页面结果一致。
5. 结果表每一行都可以点开 **K 线图** (含 MA5 / MA10 / MA20 / MA60 均线与成交量,
   鼠标移到图上可看单日开高低收、涨跌幅、成交量与均线值);
   K 线图的交互:

   | 操作 | 效果 |
   | --- | --- |
   | 滚轮上下滚 | 以鼠标位置为锚点缩放 (放大/缩小可见 K 线根数, 最少 20 根) |
   | 按住鼠标左右拖动 | 平移时间轴, 拖到最左端会自动补齐更早的本地历史 |
   | ← / → | 在同一个列表里切换上一个 / 下一个股票 (选股页按本次筛选结果, 自选股页按自选清单) |
   | 双击图表 | 复位到预设根数 (近 60 / 120 / 250 根) 并回到最新一根 |
   | 右上角 ◀ ▶ | 与 ← / → 等价, 中间显示 "第几只 / 共几只" |

   点行首的 ☆ 可以把这只股票加进 **自选股**。

所有个股 K 线详情窗口都提供「叠加个股」。可以从当前列表、自选股勾选，或按名称/代码搜索，一次添加多只；含主图最多 12 只。
叠加时所有个股合成一张紧凑图，底部仅保留一个日期轴，每只股票占一条独立窄带。以各股当前区间的首个有效收盘为 0%，K 线和均线共用百分比刻度，方便比较相对强弱；悬停可查看实际价格、成交量及基准日期。
图表根据窗口与股票数量自动分配高度，桌面窗口内最多 12 只同屏展示；十字光标、滚轮缩放和拖动平移统一联动。区间内缺少起始行情的股票采用其首个有效收盘作为基准。
停牌、上市前及缺失日期留空，回看早期日期会自动补读本地历史。支持逐只移除和失败重试；选择仅在本次详情窗口内保留。

**手工复盘表** (``/review``) 是独立的自由填写工作表。日期从左到右排列，板块、股票名和表现都填在日期格内，没有固定的板块列。
工作表铺满页面内容区，随行数展开并使用页面纵向滚动；日期较多时横向浏览，不再限制在固定高度的框内。
日期仍按从左到右递增，打开表格、切换日期范围或显示全部日期时默认定位最右侧最新日期，向左浏览历史；编辑与增删行保留当前位置。日期、格式、编辑、隐藏日期及缩放工具固定在顶部，下滑时仍可操作；窄屏工具行可横向浏览。
顶部标题和工具紧凑排列，日期表头在下滑时悬浮于工具栏下方；与表格横向滚动、缩放及日期隐藏保持对齐，点击悬浮日期仍可选择整列。
点击格子直接编辑，Shift＋点击选择矩形范围，点击行号或日期选择整行、整列。支持填充色、文字色、加粗、行情快捷样式、清空内容/格式，以及增删行和撤销/重做。
可从 Excel 粘贴多格或复制回 Excel；Enter / Tab 换格，Alt＋Enter 换行。日期区间和隐藏日期只影响显示，内容仍保存；本地日历未覆盖时明确提示仅跳过周末。
编辑会自动保存到本地数据库，失败时保留浏览器草稿；不同页面的保存版本冲突会阻止覆盖，可先导出完整 JSON 备份再重新读取。撤销历史仅在当前页面会话内保留。支持全屏和缩放。

**连板天梯** (``/stock-ladder``)

近期可查询交易日连成一张横向长表, 默认同屏约 5 日, 可调整为 3 / 5 / 10 日
(窄屏保留卡片最小宽度)。工具栏「天梯缩放」支持 50%–150%, 同时缩放日期列、卡片和连板层级;
缩小时同屏可容纳更多日期和高度, 工具栏保持原大小, 缩放比例随页面链接保留。
屏幕底部始终显示日期滚动条, 拖动即可连续浏览更早/较新日期,
也可用日期下拉框直接定位; 原有按钮作为快捷移动保留。滚动条和表格支持方向键、
PageUp / PageDown、Home / End, 触屏可直接左右滑动表格。
同一连板高度横向对齐, 日期从新到旧排列, 左侧层级固定, 所有股票随整页向下展开。
默认开启「压缩空白」, 隐藏当前可见日期没有股票的层级, 拖动时间条时实时调整连板高度;
屏幕外的卡片不撑高当前行, 数据加载完成或筛选变化后自动重新计算。
表体只渲染当前可见日期及左右各两列缓冲, 历史数据仍保留在内存缓存;
回看缓存日期不重建整表，重叠日期复用卡片及本地日K。
迷你日K只更新对应卡片, 只请求屏幕内图表, 不再为每张简图重复读取全市场股票信息。
悟道主类候选与天梯日期加载独立执行；「题材日期」指定一天，从该日本地存档读取可选题材。
向下滚动进入表格后, 日期表头固定在屏幕顶部并与股票列、底部滚动条同步横移;
滚回表格上方或离开表格区域时恢复原位。
支持悟道涨停题材下拉选择、股票/代码/当日题材搜索、主板/创业板/科创板筛选、排除 ST、只看连板,
以及按首次封板时间、封板资金或换手率排序; 每列家数随筛选变化。
股票卡片展示名称、涨幅、悟道当日主类、成交额及本地日K，代码保留在悬停提示及 K 线标题中。
同一股票不同日期的主类分别读取，缺失分类不使用行业或其他概念代替。
题材候选取指定日期全部涨停股票的悟道主类，包含首板，括号为该日各题材的股票数；
初始题材日期使用页面定位日期，随后定位或拖动天梯不会改变它。
选定题材后，保留所有日期列，仅展示各日悟道主类属于该题材的股票；
其他日期新增的同题材股票也会展示，同一股票在其他日期换题材后会隐藏。
筛选可叠加上市板块、搜索、排除ST和只看连板。
统计与缺失覆盖情况明确显示，浏览与重新统计均不触发外部板块或悟道请求。
点击打开该股票在对应交易日的 K 线图并加入自选 (K 线仍依赖本地已下载的日线)。

选择「题材日期」和具体题材后，点击「按日期和题材加入自选」，可把该日该题材的股票批量加入自选。
弹窗默认全选，支持全选、全不选及逐只排除；名单包含首板，不受天梯视口、板块、搜索或其他显示筛选影响。
可多选已有分类，或现场新建分类；填写新分类名后直接点击「加入自选」，会自动创建并归入该分类，创建失败则停止保存。
已自选股票显示当前分类，默认追加分类并保留原分类；
选择「重新设置」可整体替换分类，此模式下不选分类会归入「未分类」。备注、高亮和已有股票顺序保留，
不会重复加入股票；所选日期保存为来源日期。整批写入失败会回滚，弹窗保留勾选供重试。

涨停池按交易日自动保存在本地 SQLite 的 `ladder_snapshot` 表, 与本地日线下载独立。
页面加载、横向浏览与刷新均读取本地交易日历、涨停存档、悟道题材及日K。
只有本地日历明确为交易日的当天，在北京时间09:15–11:30、13:00–15:00，
原涨停池允许通过 AKShare 实时更新，并保存完整股票列表及取数时间；当天缓存最多复用60秒。
历史日期、午休、盘前、收盘后、休市日都不会因为浏览或刷新而联网。
缺少本地日历或股池时明确提示去数据页面下载，`refresh=true` 也不能绕过本地读取规则。
已有盘中股池在收盘后保持 `is_final=false`，不冒充最终结果，也不隐式联网补抓。
列头标明「本地存档 / 已存本地」及盘中快照状态，刷新页面或重启服务后仍可读取存档。
收盘股池由数据更新任务或 `python -m app.cli.ladder` 显式下载入库，随后页面读取本地。
当天收盘数据在15:30后准备；已有完整收盘存档不重复下载。
日期列表合并近一年的交易日与所有本地存档日期，已保存的旧日期长期保留。
近期优先通过 AKShare 获取东方财富股池，空返回或失败则尝试同花顺；超过 45 个自然日
直接读取同花顺历史涨停池及独立的连续涨停统计。连板数不使用“几天几板”标签推算。
同花顺逐页检查日期、总行数、重复代码及连板分组，成交额与行业等未提供字段留空。
快照增加 `origin=eastmoney/ths` 保存原始来源，本地读取时仍保留该字段，天梯列标明同花顺。
公开接口不保证每一天都有数据；空返回不保存为完整存档,
已有数据也不会被空返回或接口失败覆盖, 更新失败时明确标记使用本地旧快照。
空股池与接口失败会分别提示, 单日失败不妨碍其余日期展示。
滚动到相应日期才读取该列，手动“刷新本地数据”重读当前可见日期，同时最多请求三日；
仅盘中当天可更新原涨停池，不触发悟道查询。
拖动时已有请求完成后会接着读取当前停留的日期, 单日失败可手动刷新重试。不会填充示例行情。
可勾选「盘中每60秒刷新」，仅在上述交易时段、页面可见且窗口包含当天时更新当日列。
`GET /api/stock-ladder?date=YYYY-MM-DD` 返回股票、交易日列表、原始获取时间,

## 三、数据来源

全部行情数据通过 **akshare** 抓取 (不再使用 baostock)。本项目用到的接口与上游:

| 用途 | akshare 接口 | 上游 | 说明 |
| --- | --- | --- | --- |
| 交易日历 | `tool_trade_date_hist_sina` | 新浪 | 一次返回全部交易日, 约 0.4 秒 |
| 股票列表 + 当前简称 | `stock_zh_a_spot` | 新浪 | 全市场快照, 约 50 秒 |
| 日线行情 | `stock_zh_a_daily` | 新浪 | 前复权; 失败时自动退到 `stock_zh_a_hist_tx` (腾讯) |
| 历史简称 | `stock_info_change_name` | 新浪 | 由旧到新的简称序列 (不含日期) |

数据落库后, **筛选完全读取本地 SQLite**, 不再访问网络, 因此重复筛选同一日期是即时的。

### 涨跌幅是怎么来的 (重要)

akshare 的日线接口**不返回** `涨跌幅` 字段, 因此本项目由 **前复权** 收盘价按相邻两日计算:

```text
涨幅(D) = (前复权收盘(D) / 前复权收盘(D-1) - 1) × 100%
```

实测 (以交易所口径的 1440 条真实记录为基准) 两种算法的差距:

| 口径 | 最大偏差 | 说明 |
| --- | --- | --- |
| 不复权收盘价直接相除 | **2.22 个百分点** | 除权除息日会算错, 不可用 |
| 前复权收盘价相除 | **0.03 个百分点** | 与交易所公布口径一致 |

因此必须使用前复权。代价有两个, 都已处理:

* 区间内**第一个交易日**没有前收, 算不出涨幅 —— 抓取时会自动多取 15 个自然日作为预热,
  计算完再裁掉, 保证 D0 的涨幅一定有效;
* 前复权价与当日真实成交价不同 —— 结果表只展示 **涨幅与成交量**, 不展示价格,
  所以不受影响。成交量不受复权影响。

### 关于 ST 判定 (重要)

需求要求 "尽量按照所选历史日期当天的 ST 状态判断, 不能只使用股票现在的名称代替历史状态"。
akshare 能拿到两类信息, 但都不足以直接定位历史某一天:

* `stock_zh_a_spot` 给的是**当前**简称 (当天取数时它就是当天的简称, 精确);
* `stock_info_change_name` 给的是**不带日期**的简称序列 (例如
  `600082 → 海泰发展 / ST海泰 / 海泰发展 / G海泰 / 海泰发展 / ST海泰`)。

本系统的判定顺序如下 (实现在 `app/domain/st_policy.py`), 每条结果都会附带判定依据:

| 顺序 | 条件 | 结论 | 是否精确 |
| --- | --- | --- | --- |
| 1 | 本地有 **D2 当天的简称快照** | 简称含 ST 即为 ST | ✅ 精确 |
| 2 | 历史简称里**从未出现 ST** | 不是 ST | ✅ 精确 |
| 3 | D2 涨跌幅**超过该板块 ST 的涨跌幅上限** | 不是 ST | ✅ 精确 |
| 4 | 序列最后一个名字 (当前简称) **仍是 ST** | 判为 ST 并剔除 | ⚠️ 推断 |
| 5 | 当前简称已摘帽 | 判为非 ST | ⚠️ 推断 |

第 3 条的依据是交易规则: 主板 ST 股票涨跌幅上限为 **±5%**, 创业板/科创板为 **±20%**。
某一天涨跌幅超过该上限, 说明那天它**不可能是** ST —— 这是一条精确的否决证据。

结果页会显示每条命中的 ST 判定依据; 只要用到推断口径, 就会额外给出黄色提示,
提醒人工复核。如果没有 D2 当天快照, 系统**不会**静默地用今天的名称代替历史状态。

> 为什么不做成完全精确? 因为可用的免费数据源里没有 "带日期的历史简称"。
> 沪市简称变更数据在 akshare 中只有新浪这一路 (无日期), 深交所接口 (`www.szse.cn`)
> 也不提供沪市数据。使用 D2 当天快照时 (最常用的场景: 筛选最近的交易日) 就是精确的。

### 分层约定

```text
api  ──►  services  ──►  domain (纯规则 / ST 策略)
              │
              ├──►  repositories ──► SQLite
              └──►  providers    ──► akshare (新浪 / 腾讯)
```

* `domain` 不依赖任何 I/O, 因此规则可以被穷尽地单元测试;
* `providers` 通过 `MarketDataProvider` 协议抽象, 便于替换数据源或在测试中注入假实现;
* akshare 底层是无状态 HTTP, 因此每只股票各起一个线程 (线程池) 并发抓取,
  主线程负责串行落库, 不需要多进程;
* 同步任务在**独立子进程**中执行, 不阻塞 Web 事件循环; 进度通过数据库共享,
  Web 重启不影响任务。

### 选股参数

`POST /api/screen` 的请求体 (省略 `params` 即使用默认规则):

```json
{
  "date": "2026-09-18",
  "params": {
    "first_volume_ratio_min": 2,
    "first_volume_ratio_max": null,
    "first_volume_ratio_inclusive": false,
    "second_volume_ratio_min": 2,
    "second_volume_ratio_max": null,
    "second_volume_ratio_inclusive": false,
    "pct_chg_min": -5,
    "pct_chg_max": 9,
    "pct_chg_inclusive": true,
    "exclude_st": true,
    "exclude_newly_listed": true
  }
}
```

注意点:

* 区间端点写成 `null` 表示该方向不限制 (例如量比只设下限 `2`);
* `*_inclusive` 为 `true` 时是闭区间 (含边界), `false` 时是开区间 (严格不等式);
* 涨跌幅是有符号的: 负数是跌幅, 正数是涨幅;
* 响应里的 `params` 回显本次实际使用的参数, `criteria` 给出对应的文字说明
  (例如 `三日涨跌幅 (D0 / D1 / D2) 均落在 (-5%, +9%)`), 因此结果、导出 CSV 与参数始终对得上。

交互式文档: <http://127.0.0.1:8000/docs>

### 错误响应

所有业务错误都是结构化 JSON, 前端据此给出可操作的提示:

```json
{
  "error": {
    "code": "not_a_trading_day",
    "message": "2026-09-12 不是交易日, 请重新选择日期。",
    "details": { "selected_date": "2026-09-12", "suggested_date": "2026-09-11" }
  }
}
```

| code | HTTP | 含义 |
| --- | --- | --- |
| `not_a_trading_day` | 422 | 所选日期不是交易日 (附推荐日期) |
| `insufficient_history` | 422 | 所选日期之前的交易日不足两个 |
| `data_not_available` | 409 | 三日数据尚未下载 (附缺失日期) |
| `calendar_not_initialized` | 409 | 尚未初始化交易日历 |
| `sync_already_running` | 409 | 已有同步任务在运行 |
| `provider_error` | 502 | 数据源不可用 (上游超时/限流/返回异常) |
| `invalid_request` | 422 | 请求语义不合法 (例如 targeted 模式缺少 dates) |
| `validation_error` | 422 | 请求参数不合法 |

## 八、设计取舍与已知限制

1. **"数据完整" 以交易日为单位记账。** 同步完成后, 每个交易日会写入
   `synced_day` 表并记录行情条数; 筛选要求三天都在该表中, 否则返回
   `data_not_available` 并提示先更新数据, 而不是拿残缺数据出结果。
   若某天的行情条数明显少于其他两天, 结果页会给出 "数据可能不完整" 的警告。
   错误响应中的 `required_dates` 会给出补齐所需的完整交易日列表, 前端据此一键补数。

2. **次新股判定用 "本地最早K线" 作为上市日的下界。** 对窗口内上市的新股它等于
   真实上市日; 对更早上市的老股它不晚于窗口起点。两种情况下都足以判断
   "D0 之前是否已有交易记录"。akshare 没有全市场上市日期接口, 因此不做覆盖修正。

3. **股票列表来自当前快照。** akshare 只能给出 "现在" 的沪深A股列表, 因此
   最近两年内已退市、且退市时间早于首次取数的股票不会出现在结果中。

4. **涨幅由前复权收盘价推导。** 与交易所口径最大偏差约 0.03 个百分点,
   理论上会影响 "恰好落在 0% 或 7% 边界附近 0.03pp 以内" 的极少数股票。

5. **历史 ST 判定在缺少当日简称快照时使用推断。** 推断口径会在结果与提示中
   明确标注, 不会静默地把今天的名称当成历史状态。

6. **同步必须经过落库后的完整性校验。** 请求失败会继续处理其他股票，但最终仍有
   缺失或异常时任务会报告失败，不能把部分下载当作完整。已确认完整的交易日仍会保留；
   重跑增量更新可补齐缺口。`meta.last_sync_verification` 保存逐日检查结果，
   `meta.last_sync_failures` 保存问题摘要。按股票记录的进度只在有完整响应或通过校验后推进。

7. **不做并发写冲突处理。** 同一时刻只允许一个同步任务; 后台写入使用 SQLite WAL,
   Web 查询不受影响。

### 实盘验证中发现并修复的问题

1. **akshare 有 259 处 `requests.get` 没有传 `timeout`**, 上游不响应就会让线程永久阻塞
   (实测新浪对个别次新股不返回数据时卡住了整批任务)。
   现在在数据源构造时给 `requests.Session.request` 注入默认超时
   (`app/providers/http_timeout.py`), 并且抓取器加了 "连续 N 秒无任何进展就放弃剩余股票"
   的保护, 保证任务一定能收尾。
2. **akshare 不返回交易状态字段**, 早期实现把 `trade_status = None` 误判成停牌,
   导致真实数据下 "数据完整" 数量为 0。现在语义明确为:
   未提供 = 正常, 明确标记 0 = 停牌, 而停牌在 akshare 里通常表现为**当天没有这一行**。
3. **命令行任务没有记录进程号**, 进程意外退出后会一直占着 "正在运行" 状态,
   挡住后续任务。现在 CLI 会写入自己的 pid, 由 `fail_stale_runs()` 识别失效任务。
4. **当天尚未收盘就被当作最新交易日**, 盘中执行更新会把半天数据记成完整交易日。
   现在收盘 (15:30) 前会自动把可用日期回退一天。
